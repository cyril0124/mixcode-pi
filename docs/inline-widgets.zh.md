# 内联组件模式 (`[INL]`)

[English Documentation](inline-widgets.md)

MixCode Pi 提供 **内联组件模式 (Inline Widgets Mode)**（`/toggle-inline-widgets`），允许将固定在编辑器周边的扩展组件（Widget）移入可滚动的 Chat 对话流尾部。

## 概念与布局对比

默认情况下，扩展组件（如目标追踪条、定时循环计数器）固定停靠在编辑器输入框的上方或下方。当组件高度较大时，会挤压多行代码编写的垂直视口空间。

内联组件模式将扩展组件渲染移至消息流尾部：

```text
┌─ 默认固定停靠视图 ───────────────────────────────────────────────────────┐
│ [Chat 对话流视口]                                                        │
│                                                                          │
│ ┌ 编辑器上方组件停靠区 ────────────────────────────────────────────────┐ │
│ │ Goal (active) | 3 tasks remaining | tokens: 12.4k                    │ │
│ └──────────────────────────────────────────────────────────────────────┘ │
│ ── Agent-01 ──────────────────────────────────────────────────────────── │
│ > prompt 输入框                                                          │
└──────────────────────────────────────────────────────────────────────────┘

┌─ 内联组件视图 (`/toggle-inline-widgets`) ────────────────────────────────┐
│ [Chat 对话流视口]                                                        │
│                                                                          │
│ ▸ Inline · Goal (active) ─────────────────────────────────────────────── │
│ 3 tasks remaining | tokens: 12.4k                                         │
│                                                                          │
│ ▸ Inline · Goal (active) ───────────────────────────────── Agent-01 ──── │
│ > prompt 输入框 (获得完整垂直高度)                                       │
└──────────────────────────────────────────────────────────────────────────┘
```

## 核心行为与规则

1. **自然跟随滚动**：
   - 组件渲染在最后一条消息之后、排队中的 Steer/Follow-up 队列之前。
   - 向上翻页或在 Vim 模式下浏览历史记录时，内联组件随内容自然滚出视口。
2. **内联组件标题 (`▸ Inline`)**：
   - 每个内联组件左上角显示 `▸ Inline · <key>` 标题。
   - 编辑器顶部不再显示内联模式角标；`[VIM]`、`[ZEN]` 和 `[sys]` 保持原有作用。
3. **会话级与全局配置**：
   - **单 Tab 切换**：运行 `/toggle-inline-widgets` 仅切换当前 Tab。
   - **全局默认**：在 `mixcode_settings.json` 中配置 `"ui.inlineWidgets": true`，或在 `/settings` 中勾选 “Inline widgets”。
4. **侧边栏共存策略**：
   - 当右侧扩展侧边栏展开时（空输入框按 `Right`），内联组件自动适配分栏布局。

## 组件显示与 slash command

内联组件默认展开。每个组件以一行 `▸ Inline · <key>` 标题开头，正文在标题下方渲染。

### 自动行数预算

内联组件整体受一个由 chat 视口推导出的行数预算限制，避免堆叠的组件把对话记录挤出屏幕：

| 组件数 | 预算 |
|---|---|
| 1 | `clamp(floor(视口行数 * 0.6), 6, 24)` 行 |
| 2 个及以上 | `clamp(floor(视口行数 * 0.4), 6, 24)` 行 |

因此在 24 行的视口中，两个及以上组件共占 9 行，单个组件占 14 行；视口不足 12 行时，6 行的下限降为视口的一半，保证 chat 保留另一半。当自然高度超过预算时，折叠以整个组件为单位：

1. 每个正文要么完整显示，要么不显示；正文不会被截断来凑预算。
2. 完整正文按优先级分配，顺序为手动展开、最近更新、注册顺序。第一个放不下完整正文的组件就是切口：它与优先级更低的组件全部折叠为 `▸ Inline` 标题。
3. 如果连只保留标题都超出预算，整块退化为一行：`▸ Inline · N widgets · /widgets expand`；窄列下依次缩短为 `/widgets expand`、`/widgets`。

自动折叠的组件标题带 `(auto)` 标记，并保留 `/widgets expand <key>` 提示；宽度不足时依次舍弃 `(auto)` 标记、组件 key、`expand` 参数，最短保留为 `/widgets`；窄到连它也放不下时不再显示提示。标题超出宽度时直接裁剪，不换行。

`mpi ctl dump-screen --tab`/`--session` 不带视口渲染，因此不会自动折叠组件；但用 `/widgets` 手动折叠过的组件仍只输出标题行。转储当前聚焦 Tab 时会重新渲染实时画面，行数预算与屏幕一致；该路径按 `--width` 渲染，因此用与终端不同的宽度转储会重新计算尾部，可能改变哪些组件处于折叠状态。

组件高度变化时有三个需要注意的行为：

- **抗抖动而非抗变化。** 当同一批组件（key 与 `updatedAt` 均未变化）、同一预算下，整块完整展开高度变化不超过死区（2 行，预算更大时取预算的 20%）时沿用上一帧的自动决策，避免超预算的尾部帧交替折叠与展开；窗口尺寸或列宽变化、`setWidget` 更新、组件增删，或更大的内容变化都会重新计算分配，因此最近更新的组件会接手正文行数。整块完整展开能连续两帧装进预算时也会丢弃沿用中的决策，因此持续变少的组件会重新展开，而只掉一行的抖动不会把刚超预算的尾部重新撑开。
- **手动展开优先。** 用 `/widgets expand <key>` 展开的组件不会被自动折叠，即使手动展开的组件自己就超出预算，也保留完整正文：宁可让整块溢出，也不违背显式命令或截断正文；只有连标题行都超出预算时，整块才退化为那一行汇总。
- **自动决策可丢弃。** 自动决策只存在于会话状态中：某个 key 一旦被 `/widgets` 命令接管就立即失效；其余决策会在下一次重新计算时整体丢弃并按当前高度重新分配，触发条件为窗口尺寸变化、`setWidget` 更新、组件增删，或超出死区的内容变化。

使用以下 slash command 控制当前 Tab：

| 命令 | 作用 |
|---|---|
| `/widgets` | 在折叠和展开全部组件之间切换。内联尾部渲染时自动折叠算作已折叠，因此该命令会展开被预算折叠的组件，正文可以占用预算保留的行数；再次执行会把展开状态交还给行数预算，由预算重新折叠放不下的组件。停靠组件与侧边栏不受自动折叠影响，按手动折叠处理。 |
| `/widgets expand [key]` | 展开全部组件，或展开指定 key 的组件 |
| `/widgets collapse [key]` | 折叠全部组件，或折叠指定 key 的组件 |
| `/widgets toggle [key]` | 切换全部组件，或切换指定 key 的组件 |

手动折叠状态和自动决策都只保存在当前会话中。固定停靠组件和侧边栏继续使用原来的完整内容显示方式。


| 命令 / 路径 | 作用说明 |
|---|---|
| `/toggle-inline-widgets` | 切换当前 Tab 的内联组件渲染模式。 |
| `/settings` → `Inline widgets` | 配置新创建 Tab 的全局默认行为。 |
